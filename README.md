# Habibi Telegram

Телеграм-боты для Frappe: уведомления из ERP в чат, входящие сообщения,
привязка телеграм-аккаунта к пользователю Frappe. Отдельно — подключение
**личного аккаунта**: вся переписка, уведомления сервисов и служебные сообщения
Telegram попадают в сайт, а из сайта можно писать, править и удалять сообщения.

Ботовая часть написана на вебхуках и на голом Bot API: `requests` приходит
вместе с frappe, а Bot API — это обычный HTTPS с JSON. Единственная внешняя
зависимость — `telethon`, и нужна она только личным аккаунтам: MTProto — свой
бинарный протокол со своей криптографией, руками его не написать. Импорт
ленивый, без Telethon работает всё остальное.

## Почему не python-telegram-bot

Frappe v16 требует Python 3.14. `python-telegram-bot` 13.x, на котором построены
существующие интеграции, туда не ставится: он импортирует `imghdr`, удалённый из
stdlib в 3.13, вендорит urllib3 с `six.moves`, сломанным с 3.12, и тянет
`APScheduler==3.6.3`, которому нужен `pkg_resources`. Версии 20+ решают это ценой
полностью асинхронного API и удалённого `Dispatcher`.

Заодно ушла архитектурная проблема: `Updater` — это долгоживущий процесс с
polling'ом, которому в контейнерном стеке негде жить. Вебхук — обычный
whitelisted-метод, он масштабируется вместе с веб-воркерами и ничего не требует
держать запущенным.

## Установка

```bash
bench --site <site> install-app habibi_telegram
```

## Настройка бота

1. Получить токен у [@BotFather](https://t.me/BotFather).
2. Завести **Telegram Bot**, вставить токен. При сохранении токен проверяется
   через `getMe`, оттуда же подтягивается username.
3. Нажать **Set Webhook**.

Адрес вебхука собирается из имени сайта, настраивать его отдельно не нужно:

```
https://<site>/api/method/habibi_telegram.api.webhook?bot=<имя бота>
```

Схема всегда `https` — Telegram другого не принимает, а TLS в типовой установке
терминируется на прокси, и сам frappe видит только http. Если имя сайта не
совпадает с доменом, адрес переопределяется через `host_name` в `site_config.json`.

Публичный адрес обязателен: на `localhost` вебхук не зарегистрировать, приложение
откажет с объяснением. Для локальной отладки — туннель либо запрос в эндпоинт
напрямую.

Каждый апдейт подписан секретом: при `setWebhook` мы передаём `secret_token`,
Telegram возвращает его в заголовке `X-Telegram-Bot-Api-Secret-Token`, и запрос
без верной подписи до обработчиков не доходит.

Из консоли то же самое:

```bash
bench --site <site> telegram list-bots
bench --site <site> telegram set-webhook <имя бота>
bench --site <site> telegram webhook-info <имя бота>   # что о вебхуке думает Telegram
bench --site <site> telegram remove-webhook <имя бота>
```

## Отправка сообщений

```python
from habibi_telegram.client import send_message, send_file, ParseMode

send_message("Заказ <b>SO-0042</b> оплачен", parse_mode=ParseMode.HTML,
             user="manager@example.com")

send_file(frappe.get_doc("File", file_name), message="Счёт",
          user="manager@example.com")
```

Получателя можно задать тремя способами: `user` (пользователь Frappe),
`telegram_user` (документ Telegram User) или `chat_id` (например, групповой чат).
Бот берётся из `from_bot`, а если не указан — тот, что помечен как основной.

HTML чистится перед отправкой: Telegram понимает лишь несколько тегов и на любом
постороннем `<div>` отвечает ошибкой вместо отправки.

### Шаблоны

**Telegram Message Template** хранит Jinja-шаблон и переводы по языкам:

```python
from habibi_telegram.client import send_message_from_template

send_message_from_template("order-paid", context={"doc": doc}, lang="ru",
                           user="manager@example.com")
```

## Уведомления Frappe

Приложение добавляет канал **Telegram** в стандартный Notification. В самом
уведомлении появляется поле «Bot to Send From»; пустое — уйдёт от основного бота.
Получатели, у которых нет связанного Telegram User, пропускаются. Отправка идёт
через очередь `short`, поэтому сохранение документа её не ждёт.

## Входящие сообщения

Пока Telegram User не связан с пользователем Frappe, бот предлагает войти или
зарегистрироваться и не пускает дальше. После входа связь сохраняется, и
обработчики выполняются от имени этого пользователя — права Frappe работают как
обычно.

Кнопку «Signup» можно убрать: она скрывается, если в Website Settings включено
`disable_signup`. Пароль, присланный сообщением, замазывается в базе и удаляется
из чата.

Чаты и переписка видны в обычных списках **Telegram Chat** и **Telegram Message**.
На форме чата есть кнопка **Send Message** — отправляет в этот чат от выбранного
бота, и кнопка **Messages** со всей историей.

## Личный аккаунт

Бот видит только то, что написали лично ему: в чужую переписку его не позвать,
уведомления сервисов и служебные сообщения Telegram до него не доходят, и писать
от имени человека он не может. Всё это умеет клиентский протокол MTProto —
раздел **Telegram Account**.

### Подключение

1. Завести приложение на [my.telegram.org](https://my.telegram.org) → API
   development tools. Оттуда берутся **API ID** и **API Hash**; на аккаунт они
   выдаются один раз и годятся для всех подключений.
2. Создать **Telegram Account**, заполнить телефон, API ID и API Hash, сохранить.
3. **Request Code** — Telegram пришлёт код в приложение (или SMS, если больше
   нигде не залогинены). Ввести его в открывшемся окне.
4. При включённой двухфакторке следом спросится пароль.

Код и пароль передаются параметрами и в базе не сохраняются. Сохраняется ключ
сессии — он лежит в хранилище паролей Frappe и равносилен входу в аккаунт,
поэтому права на DocType есть только у System Manager и Telegram Bot Manager.

Сразу после входа приложение разбирает последние диалоги (по умолчанию 50 чатов
по 20 сообщений — настраивается на форме) и запоминает точку в очереди апдейтов.

### Как приходят апдейты

Вебхуков в MTProto нет: апдейты либо валятся в открытое соединение, либо
добираются запросом `updates.getDifference`. Выбрано второе — планировщик раз в
минуту поднимает соединение, забирает новые сообщения, правки и удаления и
кладёт трубку. Долгоживущих процессов по-прежнему нет, состояние (`pts`/`qts`/
`date`) лежит в поле **Sync State**.

Telegram помнит очередь изменений несколько дней, так что простой сайта ничего
не теряет. Если состояние всё же протухло, приложение перечитывает недавнюю
историю диалогов — дубли отсекаются по `message_id`.

Кому минута задержки дорога — есть слушатель в открытом соединении:

```bash
bench --site <site> telegram listen <аккаунт>     # для supervisor/systemd
bench --site <site> telegram list-accounts
bench --site <site> telegram sync-account <аккаунт>
```

Всё увиденное складывается в те же **Telegram Chat** и **Telegram Message**, что
и переписка ботов: один и тот же чат получает один и тот же `chat_id`, кто бы его
ни увидел. У сообщений от аккаунта заполнен **Telegram Account**, отметки
**Edited** и **Deleted in Telegram** ставятся по факту правки и удаления —
удалённое из чата в истории остаётся.

### Уведомления о новых сообщениях

Входящее сообщение поднимает уведомление в колокольчике Frappe — тот же
механизм, что у упоминаний и назначений. На форме аккаунта это раздел
**Notifications**:

| Настройка | Что делает |
|---|---|
| Notify on New Message | включает уведомления |
| Notify User | кому показывать; пусто — владельцу аккаунта из поля User |
| Notify Role | вдобавок всем, кто носит эту роль — для общего рабочего аккаунта |
| Private Chats / Groups / Channels | о чём уведомлять |

Получатель считается так: **Notify User**, если указан, иначе **User** аккаунта;
роль добавляется к этому. Administrator сам собой не подставляется — это
служебный логин, в интерфейсе под ним не сидят, и уведомление ушло бы в пустоту;
выбрать его руками в Notify User по-прежнему можно. Если получателя нет вовсе,
уведомления не создаются, а на форме висит предупреждение — включённая галочка
не должна выглядеть поломкой. Больше 20 человек за раз не оповещаем: роль вроде
System Manager может оказаться надетой на половину сайта.

Каналы выключены по умолчанию: лента новостей заваливает колокольчик за вечер.
Ещё два правила зашиты в код, без них уведомления быстро становятся мусором:

- **Одно уведомление на чат, пока предыдущее не прочитано.** В болтливой группе
  иначе набралось бы двести штук.
- **Ничего о старых сообщениях** (старше 15 минут). Первый разбор истории — это
  сотни сообщений за годы, а после простоя сайта разница приезжает пачкой.

Клик по уведомлению открывает чат целиком, а не отдельное сообщение: оттуда
видно переписку и есть кнопка ответа.

У ботов раздел тот же, но получателя надо указать явно — у бота нет владельца,
и по умолчанию оповещать некого.

Если поток входящих нужно распределять между людьми, а не показывать всем сразу,
это уже не про уведомления: заводите **Assignment Rule** на Telegram Chat —
стандартный механизм Frappe раздаст чаты по кругу или по загрузке, и назначенный
получит своё уведомление о назначении.

### Отправка, правка, удаление

На форме аккаунта — кнопка **Send Message**, на форме чата в окне отправки
появляется выбор «от бота или от аккаунта», на форме сообщения — **Edit in
Telegram** и **Delete in Telegram**. Кто выполнит действие, решает само
сообщение: прошедшее через аккаунт правится аккаунтом, отправленное ботом — ботом.

```python
from habibi_telegram.user_client import send_message, edit_message, delete_message

name = send_message("Мой аккаунт", chat_id=-1001234567890, text="Выехал")
edit_message("Мой аккаунт", chat_id=-1001234567890, message_id=42, text="Уже на месте")
delete_message("Мой аккаунт", chat_id=-1001234567890, message_id=42, revoke=True)
```

Ограничения ставит сам Telegram: править можно только свои сообщения и только
48 часов, удалять у всех — свои в любой момент, чужие — с правами администратора.
Писать можно в чат, который аккаунт уже видел: MTProto нужен не только
идентификатор, но и `access_hash`, а он берётся из кэша сущностей сессии. Если
чата в кэше нет, приложение попросит нажать **Sync Now**.

Про `parse_mode`: `HTML` и `MarkdownV2` работают, но разметку разбирает Telethon,
и набор экранируемых символов у него чуть свой.

## Свои обработчики

```python
# hooks.py вашего приложения
telegram_bot_handler = ["my_app.telegram.setup"]
```

```python
# my_app/telegram.py
def setup(registry, telegram_bot):
	registry.command("orders", show_orders)
	registry.callback_query(open_order, prefix="order:")
	registry.message(echo, group=10)


def show_orders(context):
	orders = frappe.get_all("Sales Order", limit=5, pluck="name")
	context.reply("\n".join(orders) or "Заказов нет")
```

Обработчики одной группы идут в порядке регистрации, группы — по возрастанию
(отрицательные раньше). Аутентификация висит на группе -100. Чтобы оборвать
цепочку, бросьте `StopHandling`.

В `context` лежит всё нужное: `bot` (клиент Bot API), `telegram_bot`,
`telegram_user`, `telegram_chat`, `telegram_message`, `update` (сырой апдейт),
`chat_id`, `text`, а также `reply()`, `answer_callback()` и состояние диалога
через `get_state()` / `set_state()` / `clear_state()`.

Точки расширения:

| Хук | Назначение |
|---|---|
| `telegram_bot_handler` | регистрация обработчиков |
| `telegram_update_pre_processors` | до обработчиков, на каждый апдейт |
| `telegram_update_post_processors` | после обработчиков |
| `telegram_auth_handlers` | своя аутентификация вместо login/signup |
| `telegram_start_handler` | своя реакция на `/start` |

### Пошаговые диалоги

Состояние диалога хранится в Telegram User, а не в памяти процесса — на вебхуках
каждый апдейт приходит отдельным запросом.

```python
from habibi_telegram.utils.conversation import collect_conversation_details

def ask_details(context):
	details = collect_conversation_details(
		key="delivery",
		meta=[
			{"key": "city", "label": "City", "type": "str"},
			{"key": "qty", "label": "Quantity", "type": "int"},
			{"key": "mode", "label": "Mode", "type": "select", "options": "Air\nSea"},
		],
		context=context,
	)
	if not details.get("_is_complete"):
		return

	frappe.get_doc(doctype="Delivery Request", **details).insert()
```

## DocType'ы

| DocType | Назначение |
|---|---|
| Telegram Bot | токен, username, состояние вебхука |
| Telegram Account | личный аккаунт: вход по телефону, сессия, синхронизация |
| Telegram User | телеграм-аккаунт собеседника, связь с User, состояние диалога |
| Telegram Chat | личные чаты, группы и каналы, видимые ботам и аккаунтам |
| Telegram Message | история входящих и исходящих, с пометками правок и удалений |
| Telegram Message Template | Jinja-шаблоны с переводами |
